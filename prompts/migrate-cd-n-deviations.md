# Migrate legacy `cd-N` deviations to the `deviation:` node convention

You are running inside one repo (the current working directory). Your job is to
migrate any legacy `cd-N` design-intent entries to the current `deviation:` node
convention defined in `../origin-platform/docs/methodology.md` §6. Sibling repos
live alongside this one, so that relative path resolves.

Follow these steps in order. Do not skip steps. Stop immediately if any guard fails.

## 1. Detect whether there is anything to do

1. If `this.i` does **not** exist at the repo root, AND `AGENTS.md` (if it exists)
   contains no occurrence of the literal string `cd-N` or `cd-1`/`cd-2`/`cd-3`/...
   outside the `<!-- BEGIN AGENTPREP MANAGED BLOCK -->` / `<!-- END AGENTPREP MANAGED BLOCK -->`
   markers, there is nothing to do.
2. If `this.i` exists, scan it for any of:
   - a node whose `id:` value matches the regex `^cd-\d+$`
   - a YAML key/name line containing the token `cd-N` or `cd-\d+` (e.g. a node
     literally named `cd-1:` or referenced by that name)
   - a `coverage-deviation:` node type (the older type label, if present)
3. If `AGENTS.md` exists, scan **only the prose outside** any agentprep managed
   block for references to "cd-N" or "coverage deviations" phrased the old way
   ("Approved coverage deviations (cd-N) are the complete list", etc.). Anything
   inside the managed block is regenerated by `agentprep` and you must not touch it.
4. If none of (2) or (3) found anything, skip to step 7 (clean exit).

## 2. Guards before making any change

If you found something to fix, verify all of:

1. The working tree is clean: `git status --porcelain` returns empty.
2. The current branch is the repo's default branch (usually `main`, sometimes
   `master`). Determine the default via
   `git symbolic-ref refs/remotes/origin/HEAD | sed 's@^refs/remotes/origin/@@'`.
3. You are **not** about to commit on `main`, `master`, or `dev` — you will
   create a new branch for the work.

If any guard fails, abort and write a one-line report to
`reports/migrate-cd-n-deviations-$(date -I).md` explaining why; do not modify
any files.

## 3. Create the migration branch

```
git checkout -b migrate-cd-n-deviations
```

If the branch already exists, abort with a clear message — do not reuse it.

## 4. Migrate `this.i`

For each legacy node found in step 1:

1. Change its type to `deviation:` (replacing `coverage-deviation:` or whatever
   the old type was; if the legacy form was an entry under a numbered list
   rather than a typed node, promote it to a `deviation:` node).
2. Mint a fresh opaque base32 id matching the regex `^[a-z2-7]{6,12}$`. Use
   Python's `secrets.token_bytes` + `base64.b32encode` and slice to 6–12 chars,
   lowercase, or any equivalent generator. The id must be unique across `this.i`.
3. Add a `deviates-from:` field whose value is the id of the parent standard /
   constraint / decision that this node is a deviation from. If you cannot
   determine the parent from context, insert `deviates-from: TODO` and leave a
   `# TODO: human must fill in parent id` comment.
4. Ensure `scope:`, `why:`, and `approved-by:` fields are present. If any were
   missing in the legacy form, add them with value `TODO` and a
   `# TODO: human must fill in` comment on the same line.
5. On the node's name line, leave a YAML comment recording the old id:
   `# was: cd-Nnnn` (substitute the actual old id, e.g. `# was: cd-1`).

Re-read the file after editing and confirm it parses as valid YAML. If it does
not parse, revert your changes (`git checkout -- this.i`) and abort.

## 5. Update `AGENTS.md` prose (outside the managed block only)

Rewrite any legacy phrasing to refer to `deviation:` nodes and to make clear
that discovery is by node type (every `deviation:` node in `this.i`), not by
a numbered list. Preserve the surrounding tone and structure. Do not modify
anything between `<!-- BEGIN AGENTPREP MANAGED BLOCK -->` and
`<!-- END AGENTPREP MANAGED BLOCK -->` — `agentprep` regenerates that.

## 6. Verify, stage, commit, push, PR

1. If `pytest` is configured (`pytest.ini`, `pyproject.toml [tool.pytest]`, or
   a `tests/` dir), run `pytest -q > /tmp/pytest-migrate-cd-n.txt 2>&1`. If it
   fails, abort — do not commit.
2. Inspect `git diff --name-only`. The only files allowed to change are
   `this.i` and `AGENTS.md`. If any other file shows in the diff, abort and
   report — do not bundle unrelated changes.
3. Stage only the files actually changed by name:
   `git add this.i AGENTS.md` (omit either if it was not changed). Never use
   `git add -A` or `git add .`.
4. Commit with DCO sign-off:
   `git commit -s -m "Migrate cd-N nodes to deviation: convention"`.
   No body required; subject is the whole message.
5. Push the branch:
   `git push -u origin migrate-cd-n-deviations`.
   If `gh repo set-default` has not been run, run it once non-interactively
   pointing at `origin`.
6. Open the PR:
   ```
   gh pr create \
     --title "Migrate cd-N nodes to deviation: convention" \
     --body "Migrates legacy \`cd-N\` design-intent entries to the current \`deviation:\` node convention. See ../origin-platform/docs/methodology.md §6 for the spec. Old ids are preserved as YAML comments (\`# was: cd-Nnnn\`) on each migrated node."
   ```
7. Report the PR URL.

Hard rules throughout:

- Never push to `main`, `master`, or `dev`.
- Never bundle unrelated changes; only `this.i` and `AGENTS.md` may be modified.
- Every commit must be signed off (`-s`). The repo's DCO check will reject
  otherwise.
- Never touch content inside an agentprep managed block.

## 7. Clean exit (nothing to migrate)

Write a single-line report to `reports/migrate-cd-n-deviations-$(date -I).md`
containing exactly:

```
No legacy cd-N convention found.
```

Create the `reports/` directory if it does not exist. Do not stage, commit, or
push this file — it is local-only output for the multiprompt runner to collect.
