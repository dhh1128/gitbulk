'gitbulk prune-worktrees' on a 190-repo fleet: after the per-repo-checks progress finishes, the screen is BLANK for 30-45s, then aborts with: 'open-PR fetch failed: gh exhausted 3 attempts: gh: HTTP 502'. Root: prune_worktrees.py:714 calls gh.my_open_prs([190 slugs], author=None) with NO on_progress callback. That call runs ~4 sequential paginated GraphQL searches (chunk=50 repos, each PR pulling reviewThreads(100)+labels+commits) = the silent window. A 502 (GitHub bad-gateway on an expensive search) is retried 3x by _run then raised; the whole-scope fetch failure is structural-by-design (can't reason about open-PR heads -> abort rather than mis-classify+prune). Two asks: (1) progress during the fetch; (2) echo logs/where-the-logs-are with the error for diagnosis. NOT changing the abort-is-structural safety (skipping a failed chunk could prune a worktree whose branch has an open PR). Possible follow-up: chunk=50 may itself be why GitHub 502s on this fleet (query too expensive) -> consider smaller chunk / trimmed selection.
